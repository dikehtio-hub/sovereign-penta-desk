IMPORTANT -- check DRY_RUN in .env before running:

4b. RUN THE PAPER-TRADING DAEMON (MILESTONE 14C -- REAL DEMO/TESTNET, PLUS POSITION RECONCILIATION)
----------------------------------------------------------------------------------------------------
Same webhook server as item 4 above (same endpoints, same port, same .env credentials) -- this script
is the recommended way to actually paper-trade, not an alternative system. Two differences from
running main.py directly:
    1. Always forces DRY_RUN=false, regardless of what .env says -- "paper trading" here specifically
       means real network calls to Tradovate's demo API and Hyperliquid's testnet (fake/demo money,
       real broker acknowledgments), NOT main.py's in-memory MockBrokerAdapter simulation. If you just
       want the safe, no-network simulation, use item 4 with DRY_RUN=true instead.
    2. Adds a background check every 30 seconds that asks both brokers directly for their real account
       equity and open positions, and compares that against what this system's own internal bookkeeping
       expects. If they ever disagree (a missed webhook, a manual trade placed directly on the broker's
       own platform, a bug), it's logged loudly instead of silently going unnoticed.
Command:
    .\venv\Scripts\python.exe scripts/run_paper_trading.py

Real orders get placed against whatever account your .env's TRADOVATE_URL / HYPERLIQUID_TESTNET
credentials point at -- confirm those are your demo/sim account before running this, not a live one.
Stop with Ctrl+C -- same graceful shutdown (state journal flushed, brokers disconnected cleanly) as
item 4.

Use this if something is going wrong and you need to close EVERY open position across EVERY strategy

----------------------------------------------------------------------------------------------------
8. DISASTER RECOVERY: STATE JOURNAL & CONNECTION HEALTH MONITOR (AUTOMATIC -- NOTHING TO RUN)
----------------------------------------------------------------------------------------------------
Two safety nets that run automatically whenever the webhook server (item 4) is running -- there is no
command for either, this section is here so you know they exist and where to look:

    STATE JOURNAL: every open position, realized PnL, and circuit-breaker cooldown is written to
    state\runtime_state.json after every processed signal and on every clean shutdown. If the server
    crashes or is restarted, it reads this file back on startup and picks up exactly where it left off
    -- open positions are not "forgotten." Override the file's location with the STATE_JOURNAL_PATH
    environment variable if you ever need to. This folder is intentionally excluded from git (see
    .gitignore) -- it's live runtime state, not source code.

    CONNECTION HEALTH MONITOR: pings Tradovate and Hyperliquid every 10 seconds in the background. If
    either one hasn't answered successfully for more than 30 seconds, a CRITICAL line appears in the
    server's console output naming which broker is down. It logs again when the connection recovers.
    Just watch the console (or wherever you're piping the server's logs) -- no separate command to run.
